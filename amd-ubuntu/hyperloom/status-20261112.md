## What the 3 problems are

- **The sandbox problem:** Hyperloom's helper agents could not read the ATOM code, the aiter code or the model's config, so they could not suggest any code changes. The cause was that the `claude` program was not on PATH inside the container.
- **The profile breakdown:** this measures how much GPU time each kind of kernel uses (MoE expert math, all-reduce, attention, and so on). The earlier profile came from one tool at 64 users only, and that tool rated its own confidence as low. We are redoing it with `rocprofv3` at 1, 64 and 256 users to see where the time really goes.
- **The corrected candidates:** these are the speed-up ideas the profile pointed to, tested with our own scripts instead of Hyperloom's broken runs:
  - **a8w4:** run the MoE expert math with FP8 activations instead of BF16.
  - **Expert parallel:** split the experts across GPUs instead of tensor parallel, to cut the all-reduce time.
  - **MoE tile tuning:** better kernel tile settings for the MoE math. Put off for now.

  Each one is checked for both speed and GSM8K accuracy.
